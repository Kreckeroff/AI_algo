## 1. Что мы вообще строим

Не «одну нейросеть, которая торгует».  
Мы строим **умного помощника для алго-скриптов** в IT Algo:

1. Понять, **улучшило ли** изменение скрипта результат (сравнение «до / после»).
2. Предложить **конкретную правку** графа (добавить фильтр, сменить период, стоп и т.д.).
3. Делать это **только когда правка реально помогает** — не всегда.

Сейчас фокус — **качество этой логики на исторических данных**.  
Вшивание в прод Desktop (**Advisor в UI**) — сознательно отложено.

## 2. Что уже умеем (итог дня)

| Вопрос бизнеса | Ответ |
|----------------|--------|
| Умеем ли отличить полезную правку от вредной? | **Да.** Модель правильно угадывает ~90% случаев (C19). |
| Если применять правки всегда — лучше ли станет? | **Нет.** «Всегда чинить» сильно ухудшает результат. |
| Если применять правки выборочно? | **Да.** Выборочное правило даёт **плюс** к базовому PnL (~+48 на тестовой симуляции). |
| Стали ли стратегии стабильно бить рынок? | **Ещё нет.** Это не доказанный торговый edge; это умный советчик по правкам. |
| Можно ли уже показывать в продукте? | **Пока нет** в прод-UI. Есть офлайн-модель и корпус примеров. |

## 3. История одним абзацем

Мы научили систему сравнивать тысячи пар «скрипт до правки / скрипт после» на акциях и фьючерсах MOEX.  
Потом выяснили: рынок часто «пилит» (боковик), а трендовые скрипты в пиле портятся.  
Сделали детектор режима рынка (тренд / пила / переход).  
Пробовали чинить скрипты «всегда» — стало хуже.  
Научились чинить **только когда рынок в пиле и модель уверена** — стало лучше.

## 4. Словарь (вместо жаргона)

| Термин в коде | Простыми словами |
|---------------|------------------|
| **Скрипт / `.italgo`** | Алгоритм в конструкторе (блоки индикаторов + вход/выход). |
| **Бэктест** | Прогон скрипта на истории котировок. |
| **PnL** | Прибыль/убыток за период (в пунктах цены / условных единицах бэктеста). |
| **Δ / delta** | Разница: «после правки минус до». Плюс = правка помогла. |
| **Intervention / правка** | Автоматическое изменение графа (фильтр, период, стоп…). |
| **Kind** | Тип правки (`chop_gate` = не входить в пилу; `mr_overlay` = добавить отскок в пиле). |
| **Policy / ranker / модель** | Классификатор: «эта правка здесь поможет?» Да/нет + вероятность. |
| **CV / AUC ~0.9** | Качество угадывания на проверке: чем ближе к 1, тем лучше отличает полезные правки. |
| **Promote / `38p-*`** | Отобранные в корпус «хорошие» варианты скриптов после обучения. |
| **Chop / пила** | Боковик: цена ходит туда-сюда без тренда. |
| **Trend** | Направленное движение вверх или вниз. |
| **Transition** | «Серая зона» между пилой и трендом. |
| **Selective apply** | Применять правку только если: рынок в пиле **и** модель уверена. |
| **Buy&hold** | Купил и держит без сделок — пассивный эталон. |
| **§7G** | Правило: пока **не** вшиваем ИИ в прод Desktop. |
| **C17 / C18 / C19** | Номера волн обучения (как спринты экспериментов). |

## 6. Что в бэклоге сейчас (приоритеты)

### Готово / почти готово
- Сравнение скриптов + разбор сделок (ядро данных).
- Корпус ~26 базовых скриптов + волны promotes `27p`…`37p` + `38p_*_sel`.
- Учёт дивидендов в обучении (акции).
- Сравнение с buy&hold в метках.
- Детектор рынка тренд/пила + выборочные правки (C19).

### Дальше (когда вернёшься домой)
1. **History-window sweep** — гонять разные длины истории (1 день…несколько лет) на другом ПК.
2. **Combo-правки** — несколько изменений сразу (не по одному).
3. **Advisor в продукте** — когда качество модели достаточно (сейчас §7G = не трогаем прод).
4. **Конструктор из текста** / standalone UX — после зрелости моделей.
5. Desktop BT: родной buy&hold + дивиденды в движке (ещё долг).

Полный список: [`BACKLOG.md`](BACKLOG.md). Снимок статусов — § «Снимок 2026-08-21» в начале файла.
