## Одна фраза

**Отдельный продукт** AI_algo: помогает **собирать**, **улучшать** и **оценивать** торговые стратегии — с чатом, сборщиком и своими данными (CSV / брокер).  
Тот же функционал **встраивается в IT Algo Desktop** и доступен с коробки.  
Стратегии обмениваются **файлом** между standalone и Desktop.

См. [`PRODUCT_BOUNDARY.md`](PRODUCT_BOUNDARY.md), [`work/STANDALONE_PRODUCT_UX.md`](work/STANDALONE_PRODUCT_UX.md), [`work/platform/INTEGRATION_INTERFACES.md`](work/platform/INTEGRATION_INTERFACES.md).

## Модули

```text
┌──────────────────────┐   Inference / Ingest / Train   ┌─────────────────────────────┐
│  Clients             │ ◄────────────────────────────► │  AI_algo (ядро)              │
│  · Desktop           │                               │  Chat · Builder · Compare    │
│  · Standalone shell  │   CSV / broker / Desktop data │  Advisor · Signal · DSL      │
└──────────────────────┘                               └─────────────────────────────┘
```

| Модуль | Пользовательская ценность | «Своя» модель? |
|--------|---------------------------|----------------|
| **Chat** | Диалог: комментарии, создание/правка стратегий | LLM + tools (build/compare/…) |
| **Builder** | Промпт/чат → готовый граф; сам добирает периоды/связки | LLM + DSL; позже ранжировщик графов |
| **Compare** | После правки: лучше/хуже + советы | Нет (метрики + разбор сделок + LLM-текст) |
| **Advisor** | Советы по портфелю, статистике и **паттернам сделок** | Правила + LLM |
| **Signal** | Оценка направления/режима по рынку | Да, лёгкая tabular на CPU |
| **Composition** | `EMA(RSI)`, мульти-ТФ, режимы тренд/MR | DSL + обучение на составных фичах |
| **Data** | CSV upload + брокер; ingest из Desktop | — |

### Разбор исторических сделок (обязательная способность)

ИИ должен смотреть не только PnL/DD, но и **список сделок бэктеста** (и позже — брокерскую историю):

- находить проблемы: «пила» во флэте у трендового скрипта, overtrading, серии убытков, перекос long/short;
- писать **причину** и **конкретную доработку** (фильтр ADX, запрет шортов, hold, SL/TP, сессия…);
- учитывать режим скрипта (тренд / mean-reversion / breakout) — советы разные.

Данные в Desktop уже есть: `BacktestSnapshot.trades` (+ отдельно брокерская история Finam/Tinkoff в SQLite).

## Цель оптимизации (что «хорошо» для ИИ)

ИИ **стремится** к двум вещам сразу:

1. **Положительный winrate** (где это уместно режиму), и  
2. **Максимальный чистый PnL** (доход после издержек/логики бэктеста).

Но приоритет **зависит от режима стратегии** — нельзя одинаково жать WR на тренде и на mean-reversion.

| Режим | Приоритет | Норма по WR | Поведение ИИ |
|-------|-----------|-------------|--------------|
| **Trend-following** | **1) PnL → 2) WR** | часто **&lt; 40%** — это нормально | Сначала искать / улучшать **макс. PnL** (и приемлемый DD); затем пытаться **подтянуть WR** без убийства PnL |
| **Mean-reversion / другие** | PnL **и** WR вместе (оба важны) | обычно выше, чем у тренда | Не жертвовать устойчивым WR ради разового PnL без оговорок |
| **Breakout** | ближе к тренду: PnL first | может быть умеренный WR | Как trend, пока не размечен иначе |

**Следствия для compare / ranker / chat:**

- Не считать трендовый скрипт «плохим» только из‑за WR 30–40%, если PnL/DD сильные.
- Вердикт `better` для тренда: в первую очередь рост **net PnL** (при не худшем DD); рост WR — бонус / следующий шаг улучшения.
- Советы ИИ на тренде: «сначала зафиксируй/увеличь PnL, потом фильтры/выходы для WR», а не «подними WR любой ценой».

Детали в backlog (цель оптимизации) и compare-политике.

## Не цель

- Обучить свой GPT с нуля
- Обещать точность прогноза цены / гарантированную прибыль
- Засунуть все комбинации индикаторов в одну гигантскую сеть
- Делать «урезанный» AI в Desktop и «полный» только в standalone — **паритет способностей**

6. Portfolio advisor
