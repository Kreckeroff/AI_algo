## Модель

**AI_algo** — самостоятельный продукт (сервис + модели + спеки).  
**IT Algo Desktop** — клиент, который подключается к AI_algo по стабильным интерфейсам.

```text
┌─────────────────────┐         контракты API / события          ┌─────────────────────┐
│  it-algo-desktop    │  ────── данные (ноды, бары, метрики) ──► │      AI_algo         │
│  (терминал,         │  ◄──── ответы (граф, вердикт, сигнал) ── │  (inference + train) │
│   конструктор,      │                                          │                     │
│   бэктест)          │  опц. dev: обучение «на живых» данных    │                     │
└─────────────────────┘                                          └─────────────────────┘
```

Интеграция = адаптер в Desktop, **без** вшивания логики обучения/LLM внутрь релизного ядра Desktop.

## Что принадлежит кому

| Зона | AI_algo | IT Algo Desktop |
|------|---------|-----------------|
| Модели, веса, пайплайн обучения | ✅ | ❌ |
| DSL/схема графа скрипта (канон для AI) | ✅ контракт + валидатор | ✅ runtime исполнение графа |
| UI конструктора / бэктест | ❌ | ✅ |
| Интерпретация «лучше/хуже» | ✅ | передаёт метрики A/B |
| Сбор сырых рыночных данных | получает | источник |
| Квоты / биллинг AI (если SaaS) | свой gateway или через it-algo-site | показывает лимиты |

---

## Два режима данных для обучения

| Режим | Когда | Как |
|-------|-------|-----|
| **Export** | prod / любой стенд | Desktop (или CI) выгружает ноды, OHLCV, фичи, бэктесты → AI_algo ingest / файлы |
| **Dev-integrated** | ветка `dev` / локальный стенд | Desktop стримит или пушит батчи в AI_algo Train API; обучение крутится рядом с dev |

Прод-релиз Desktop **не** обязан уметь учить модель — только вызывать inference и (по политике) слать анонимизированные телеметрии/экспорты.
